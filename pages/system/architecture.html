SYSTEM ARCHITECTURE

From Sensor Input to Mechanical Action.

AquaSense uses a layered embedded-system architecture in which sensing, processing, decision-making, actuation and user feedback work together to automate a conventional water dispensing mechanism.

ARCHITECTURE FLOW

Complete System Signal Path

Information moves from the physical environment into the sensing layer, through the Arduino control layer and finally into mechanical action and user feedback.

01
PHYSICAL INPUT

User Places a Hand Near the Dispenser

The interaction begins when a user places a hand within the sensing region in front of the ultrasonic sensor.

No physical button, switch or tap contact is required to initiate the sensing process.

02
SENSING LAYER

HC-SR04 Measures Distance

The ultrasonic sensor emits a sound pulse and measures the time required for the reflected echo to return.

This timing information is sent to the Arduino Uno for distance calculation.

03
PROCESSING LAYER

Arduino Uno Processes the Sensor Data

The Arduino Uno acts as the central processing unit of AquaSense.

It converts ultrasonic echo timing into a distance measurement and evaluates that value using the programmed control logic.

04
DECISION LAYER

Detection Threshold Is Evaluated

The controller checks whether the measured distance satisfies:

Distance > 0 cm AND Distance ≤ 15 cm

If the condition is false, monitoring continues. If it is true, Arduino begins the dispensing sequence.

05
ACTUATION LAYER

Dual Servo Motors Operate the Tap

Arduino sends position commands to both SG90 servo motors.

The servos move from the closed position of 0° to the programmed open position of 90°.

06
MECHANICAL OUTPUT

Tap Mechanism Opens

Servo rotation is converted into physical movement of the tap mechanism.

Water is allowed to flow for the programmed dispensing period of approximately three seconds.

07
RESET

Tap Automatically Closes

After the dispensing period, Arduino commands both servos to return to 0°.

The mechanical tap closes and the system returns to monitoring mode.

SYSTEM LAYERS

Five Layers of the AquaSense Architecture

Separating the prototype into functional layers makes the complete engineering system easier to understand, troubleshoot and expand.

01

Input Layer

Represents the physical interaction between the user and the system. A hand entering the sensing region becomes the trigger condition for the automation process.

02

Sensing Layer

The HC-SR04 ultrasonic sensor detects the presence and distance of an object without requiring physical contact.

03

Control Layer

Arduino Uno receives sensor data, performs calculations, applies decision logic and coordinates all system outputs.

04

Actuation Layer

Two SG90 servo motors receive position commands from Arduino and convert them into controlled mechanical rotation.

05

Feedback Layer

The 16×2 I2C LCD communicates system status to the user during monitoring, dispensing and completion.

CENTRAL CONTROL

Arduino Uno Is the Core of the Architecture

Every major subsystem communicates directly or indirectly through the Arduino Uno.

IN

Sensor Input

Arduino generates the HC-SR04 trigger pulse and reads the returning echo signal to determine object distance.

CPU

Logic Processing

The controller calculates distance and determines whether the detection threshold has been satisfied.

OUT

Servo Control

Arduino generates position commands that control the open and closed positions of both SG90 servo motors.

UI

LCD Communication

Arduino sends status information to the LCD through I2C communication for clear user feedback.

CONNECTION MAP

How the Main Components Communicate

Each subsystem has a defined relationship with the Arduino controller.

A

HC-SR04 → Arduino Uno

The ultrasonic sensor provides distance measurement information through its trigger and echo interface.

Trig → Digital Pin 9
Echo → Digital Pin 10

B

Arduino Uno → Servo 1

Servo 1 receives its position command from Arduino.

Signal → Digital Pin 6

C

Arduino Uno → Servo 2

Servo 2 operates together with Servo 1 during the dispensing sequence.

Signal → Digital Pin 7

D

Arduino Uno ↔ 16×2 I2C LCD

The LCD uses I2C communication to receive text and system-status data from the Arduino Uno.

On a standard Arduino Uno:
SDA → A4
SCL → A5

ENGINEERING VIEW

Signal Flow and Power Flow Are Different

Understanding this distinction is important when designing, wiring and troubleshooting the physical prototype.

SIG

Signal Flow

Signal connections carry information and control commands.

Examples include the ultrasonic trigger and echo signals, servo control signals and I2C communication with the LCD.

PWR

Power Flow

Power connections provide the electrical energy required for the Arduino, sensor, display and servo motors to operate.

Servo motors can draw significantly more current than logic-level sensors, so power delivery must be considered carefully in the physical implementation.

GND

Common Ground

When an external power supply is used for the servo motors, the external supply ground and Arduino ground should share a common electrical reference for reliable control signals.

ARCHITECTURE SUMMARY

One Complete Information Path

User's Hand → HC-SR04 Ultrasonic Sensor → Arduino Uno → Distance Calculation → Threshold Decision → Dual SG90 Servo Motors → Mechanical Tap Movement → Water Dispensing → Automatic Closing.

In parallel, the Arduino Uno communicates with the 16×2 I2C LCD to provide real-time status information throughout the operating cycle.
